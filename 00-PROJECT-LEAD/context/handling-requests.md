# Handling Matt's requests

Load when: scoping, prioritising, or deciding what to work on.

## Scope

- **The request in this chat is the scope.** The open-items list in `00-PROJECT-LEAD/STATE.md` is background, not your agenda.
- Mention an open item only if Matt asks, or if it directly blocks what he asked for. "Blocks" means his request can't be done without it. Being higher on an old list does not count.
- If Matt says a topic is out of scope for this chat, drop it. Don't bring it back later in the chat.

## Priority

- Matt sets priority. When he says something is the top priority, it is. Don't argue for a different order from an older handoff.
- If you think something he hasn't mentioned will actually break his request, say so once, in one line, with the evidence. Then follow his call.

## Keep the whole request

Requests often have several parts (for example: explain week-1 picks, find patterns against the market, and run many backtests and reverse experiments every week).

1. Before planning, write the parts as a numbered checklist, using Matt's words.
2. Before handing over a plan or prompt, go down the checklist and say where each part is covered.
3. If you cut, shrink, or delay any part, or add a gate he didn't ask for, say so **first**, with the reason, and ask.

On 2026-09-17 a prompt quietly reduced "extensive backtesting and reverse experiments" to "store explanations for backtests" and added "Part B waits until Part A is live." Matt had to say "don't forget what I wanted from the start." This checklist exists to stop that.

## Model performance

- Finding an edge is active work, done through the platform (see `00-PROJECT-LEAD/PROJECT-CHARTER.md`). Build what Matt needs to look for one.
- Don't volunteer judgments about how good the current model is. If Matt asks, answer with numbers from platform runs and name the run.
- Never cite the May 2026 experiment runs. Matt considers all of them flawed. Use runs made since 2026-09-15.
- A good week (for example, 12–3 in week 1) is not a reason for a luck or leakage warning in chat.

## Files

- Propose changes, then make them when Matt asks. Don't edit a task prompt or plan he hasn't asked you to change.
- When the change is the thing he asked for ("write me a prompt"), write it.

## When to ask

Ask when the decision is Matt's: priority, scope, go-live, anything that changes production, anything irreversible. Don't ask about things you can check yourself; check them.
